## 一、选题背景与意义

### 1.1 问题

让非专业用户用中文口语指挥机械臂完成抓取，需要跨越三层鸿沟：

| 鸿沟 | 具体表现 |
|:---|:---|
| 语言 → 意图 | 「把那个绿的拿过来」没有固定句式，不能靠命令词匹配 |
| 意图 → 目标 | 要从画面里判断"哪个是绿的"，而不是靠预设坐标 |
| 目标 → 动作 | 视觉位置到六个关节角的映射是高维非线性问题 |

传统方案要求用户学习命令词、物体固定在标定位、每个任务单独编程。**本项目要让这三步都由模型完成。**

### 1.2 意义

- **工程意义**：验证「大模型做语义决策 + 小模型做动作生成」的分层架构在低成本桌面机械臂（SO-101，约 ¥1500）上是否可行
- **教学意义**：完整走通数据采集 → 训练 → 推理 → 真机迁移的全链路，形成可复用的工程范式
- **应用前景**：语音控制适合双手被占用、需要快速示教的场景（实验室、康复辅助、教学演示）

## 二、国内外研究现状

### 2.1 技术路线演进

| 阶段 | 代表工作 | 核心思想 | 局限 |
|:---|:---|:---|:---|
| 行为克隆 | ACT / ALOHA (2023) | 动作分块（action chunking）+ 低成本双臂硬件 | 不理解语言，单任务 |
| 扩散策略 | Diffusion Policy (2023) | 用扩散模型建模多模态动作分布 | 推理慢，语言条件弱 |
| 通用策略 | Octo (2024)、OpenVLA (2024) | 大规模跨机器人数据预训练 | 参数量大（7B），难部署 |
| VLM 融合 | RT-2 (2023)、π0 (2024) | 把动作离散成 token 或流匹配 | 需大规模数据与算力 |
| 轻量化 | **SmolVLA (2025)** | 500M 参数，为小数据微调设计 | 生态较新 |

### 2.2 与本项目的关系

| 工作 | 借鉴 | 差异 |
|:---|:---|:---|
| **ACT** | 动作分块、VAE 结构、训练流程 | **实测其 `forward` 不读 `task` 字段**，无法做语言条件 |
| **SmolVLA** | 语言条件架构、小数据微调 | 本项目下一步改用 |
| **LeRobot** | 数据集格式（v3）、训练/评测脚本 | 直接复用 |
| **RT-2 / π0** | "VLM 做语义、动作专家做控制"的分层思想 | 我们不用 7B 模型 |

### 2.3 现有方案的共同问题

1. **VLM 输出坐标**：多数方案让 VLM 给像素坐标再几何变换，误差累积
2. **语言与动作耦合过紧**：端到端模型难以独立评估语言层
3. **仿真与真机割裂**：两套代码，迁移成本高

### 2.4 本项目的切入点

**VLM 只做语义决策（翻译 + 存在性确认），不输出坐标；位置由 VLA 从图像学习。**
这样语言层与动作层可以独立迭代、独立评估。

## 三、研究内容与关键问题

### 3.1 研究内容

1. **分层架构设计**：VLM（语义）+ VLA（动作）的边界定义与接口契约
2. **数据采集与设计**：如何设计数据使语言条件真正生效
3. **策略选型与训练**：ACT / SmolVLA 的能力边界对比
4. **仿真到真机迁移**：同一套上层代码适配两种后端

### 3.2 三个关键问题

| 问题 | 难点 | 本项目的验证方式 |
|:---|:---|:---|
| **Q1 语言条件是否会生效** | 数据设计不当会让模型学"按位置选"而非"按指令选" | 固定场景、只换指令，比较动作距离（`check_language_conditioning.py`） |
| **Q2 小数据能否学会抓取** | 150–250 条是否足够 | 自建仿真场景 + IK 生成演示 + ACT 训练 |
| **Q3 仿真结论能否指导真机** | 图像域差异、物理差异 | 明确划分"仿真能验证"与"只能真机验证"的边界（`docs/experiments.md`） |

## 四、技术路线

### 4.1 三层架构

```
中文语音 → 唤醒/ASR → 文本
                        ↓
              VLM（只做语义）
    中文 + 桌面图像 → 结构化指令（英文模板 + 存在性 + 方位）
                        ↓ 唯一接口
              VLA（只做动作）
        图像 + 英文指令 → 16 步 × 6 关节动作块
                        ↓
                  机械臂执行 → 语音反馈
```

**三条不变量**（代码中有断言与测试保障）：

1. VLM 不输出坐标，只出固定模板英文指令
2. 方位 `position_hint` 与语音回复不进入 VLA 输入
3. ROS2 节点只做消息转换，逻辑全在 `voice_arm_core`

### 4.2 数据采集设计（决定语言条件成败）

| 原则 | 具体做法 | 为什么 |
|:---|:---|:---|
| 位置必须打散 | 方块在 6×16 cm 区域内随机 | 位置固定会让模型背轨迹 |
| 颜色与位置必须交叉 | 每条 episode 重排三块并打乱颜色 | 否则模型学"按位置选"，忽略指令 |
| 指令模板统一 | 只允许 `pick up the {color} cube` | 模板不一致会导致文本嵌入偏移 |
| 反例 | geonmin-kim 公开数据集颜色与位置绑定 | 其 `effective` 结论实为位置偏差所致 |

### 4.3 仿真到真机的映射

只替换 `robot/real.py` 的 7 个方法，其余 6 个环节（采集/训练/推理/评测/可视化/编排）代码完全共用。

## 五、可行性分析（已有工作基础）

### 5.1 已完成并实测

| 项 | 结果 | 证据 |
|:---|:---|:---|
| 代码规模 | 3192 行 Python，37 个单测全绿 | `python3 -m pytest -q` |
| 仿真环境 | MuJoCo 3.17，双相机 640×480，三色方块 | `scripts/preflight.py` 三项通过 |
| 数据采集 | 150 条 / 13350 帧，位置随机、颜色解耦 | `check_dataset.py [OK]` |
| 策略训练 | ACT 52M，15000 步，loss 6.92 → 0.15 | 训练日志 |
| **抓取精度** | **末端-目标距离 0.0 cm（末段均值 0.1 cm）** | `render_replay_video.py` |
| 抓取效果 | 绿块画面上抬 106 px，红蓝不动 | 视频 + 数值验证 |
| ROS2 层 | 3 包编译通过，5 节点可执行 | `colcon build` 6.08 s |

### 5.2 已验证的负结果（同样是成果）

**ACT 不支持语言条件**：`grep` 实测其 `forward` 处理 `task` 的代码行数为 **0**，
而 SmolVLA / π0 为 6。用三色数据训练 15000 步后，三种指令的动作距离仅 **0.00016**（几乎为零）。

**价值**：这是文献里很少明确写的工程事实，避免了后续在错误方向上投入算力。

### 5.3 风险与对策

| 风险 | 概率 | 对策 |
|:---|:---:|:---|
| SmolVLA 显存不足 | 中 | 云端 4090（约 ¥50–200），或本地 batch 1 + LoRA |
| 语言条件仍不生效 | 中 | 已有排查清单：颜色位置绑定 / task 标注 / 模板一致性 |
| 真机到货延迟 | 中 | 软件部分可独立完成，真机只影响最后 2 周 |
| 仿真与真机域差异 | 高 | 已明确边界，仿真只验证逻辑，抓取成功率必须真机测 |

## 七、预期成果与创新点

### 7.1 预期成果

1. 一套开源的「中文语音 → VLM → VLA → SO-101」完整系统
2. 仿真与真机共用同一套上层代码的工程范式
3. 可复现的实验数据：数据集、训练曲线、语言条件对比、抓取成功率

### 7.2 三个创新点

**1. VLM 不输出坐标的分层设计**

现有方案多让 VLM 输出像素坐标再做几何变换，误差会累积。
本项目让 VLA 直接从图像学习位置，VLM 只做语义决策——
语言层与动作层可独立评估、独立迭代。

**2. 面向语言条件的数据设计规范**

总结出四条铁律（位置打散、颜色位置交叉、模板统一、每类 50 条），
并用实测反例说明违反后的后果：geonmin-kim 数据集的 `effective` 结论实为位置绑定造成的假象。

**3. 完整的仿真→真机链路映射与踩坑记录**

15+ 个真实 bug 的现象、根因、修复方式（见 `docs/pitfalls.md`），
包括 ACT 不读 task、归一化管线缺失、单位混用等**不报错但结果错**的隐蔽问题。
